# Capability matrix (updated 2026-10-31)

The capabilities follow from the data the service actually exposes ([discovery/](discovery/README.md); certainty tags are explained there). Each capability is a domain operation and may consist of several requests.

Channels: **A** = JSON `/api/*`, **B** = RSC page, **C** = server action.

Status:
- **implemented**: available in the CLI and as an MCP tool; a live-health mark follows it where the service was re-checked after the 2.0 redesign (see below)
- **feasible**: requests known and response shape understood, not implemented
- **unclear**: data semantics not yet understood
- **deferred**: low priority or out of scope

Live health as of 2026-10-31, after the redesign of 2026-10-29 ("deweloperuch 2.0", [discovery/README.md](discovery/README.md) section 6) and the repairs that followed: ✅ passed a live e2e run (2026-10-29 for the tools that needed no repair, 2026-10-31 for the repaired ones), 🟡 partly working or verified by probe only (not run end to end), 🔴 broken. A tool is never marked ✅ without a live e2e run. Sources: the live e2e runs of 2026-10-31 on the integrated repairs (three runs, 116 requests, no STOP; every test passes except three expected xfails: the two `rank_locations` tests at powiat level, where `map/powiat-stats` is gone and the tool answers „service changed”, and `get_developer` of a known developer in an unknown city, whose page has no `hero` props and no 404 marker); the e2e run of 2026-10-29 on the code before the repairs (36 failed, 26 passed and 12 errored in `test_live_mcp`; 2 failed in the rankings; 3 failed in the transactions; the buildings, valuation, developer search, investment search and CLI tests passed); 19 probe requests of 2026-10-30, 1 of the morning of 2026-10-31 and the 30 of round B2 on 2026-10-31. Round B2 found that a request with an **empty `_rsc`** gets the RSC payload (no redirect, T63); the repairs read the renamed props (T57) and moved the three tools whose routes were removed to the replacements named in the rows (T58).

13 MCP tools are implemented: `search_locations`, `search_offers`, `get_offer`, `search_investments`, `get_investment`, `search_developers`, `get_developer`, `get_market_statistics`, `get_transaction_statistics`, `rank_locations`, `get_building`, `estimate_property_value`, `get_government_statistics`.

## Design principles for the tools

- List results always return `total` and a truncation indicator, so the model knows to narrow the filters.
- Identifiers in outputs are those accepted by the "get" tools: `investment_slug`, `offer_id`, `building_slug`, `developer_slug`, `city_slug`.
- Large arrays (comparable transactions, investment offers) are trimmed with a `limit` parameter and an `omitted` field.
