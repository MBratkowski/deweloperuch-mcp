## [0.2.0] - 2026-11-02

### Added
- `get_transaction_statistics` / `stats transactions`: incomplete newest periods are marked. Each such period has `incomplete: true` (MCP: only when true; CLI `--json`: a bool on every period; the text table marks it with ` *` and a legend line), and the result has `last_complete_period` (omitted when it cannot be judged). The hint names the incomplete periods and the last period with a usual count (its data may still change); for small series it says there are too few transactions to judge. The rule is the package's own [W]: the longest trailing run of periods (at most 12 months or 4 quarters) with fewer than half of the median count of the reference window before it; not judged when that median is below 10 transactions or with fewer than 3 reference periods (open question T46). The `note` text, the tool description, the server instructions and the prompt `porownaj_miasta` changed accordingly.
- `estimate_property_value` / `valuation estimate`: `low_confidence` (`true` exactly when the estimate rests on fewer than 5 comparable transactions; present on every estimate, `false` included; omitted without one). The hint carries a caveat with the facts (number of transactions, radius, months), or a softer sentence when only the radius reached the service's ceiling of 1000 m. The CLI prints it as an `Uwaga: …` line and the valuation cautions as `Wskazówka: …`. The prompt `ocen_oferte` tells the model to pass the caveat on.
- `get_building` / `buildings get`: `non_regular_transactions` (counts of transactions with a classification other than `regular`, e.g. shares and enforcement sales; omitted in MCP when none, `{}` in CLI `--json`; the CLI prints a `Transakcje inne niż zwykłe: …` line) and `hint` (e.g. an empty neighbourhood trend). The service's averages probably do not include non-regular transactions (checked in one building, T48).
- `search_offers` / `offers search`: `items[].district`, the investment's district spelled as `search_locations` names it, so it can be passed back as `district` (absent when the service gives none, e.g. Sopot; in the CLI only in `--json`). A search in a district reads the district's own list, and an unknown district has its own error (CLI exit code 7) that lists the city's real district names, and a district written otherwise is found (see the entry below on the districts). See [docs/mcp/tools/search_offers.md](docs/mcp/tools/search_offers.md).
- `get_market_statistics` / `stats market`: `as_of`, the day the service gave its offers for (the CLI head line ends with „ · stan na RRRR-MM-DD”), and `top_developers[].developer_name` (the CLI shows `name [slug]`). The prompt `porownaj_miasta` carries `as_of` into its table.
- `get_government_statistics` / `stats government`: `source` can be `Eurostat` (the monthly demography of `polska`), and `average_area` carries a `note` that its last year is partial („Ostatni rok (2026) bywa niepełny: GUS dopisuje go kwartałami, więc porównuj go ostrożnie z pełnymi latami.”).
- `rank_locations` / `stats cities`: `indicator` (CLI `--indicator`) ranks the 66 cities with powiat rights by a GUS or NBP indicator instead of by transactions: `unemployment_rate`, `average_wage` (the average monthly gross wage, the average for the year; unit `PLN/mies.`), `dwellings_completed` and `dwellings_started` (sums of the last 12 months), `average_dwelling_area`, `natural_increase` and `nbp_price_per_m2` (the NBP transaction price of the secondary market, 17 cities). `sort` takes `value_desc` (default) or `value_asc` with it. The result has `indicator`, `unit`, `period` and, per city, `value` and `stats_url` (the city's page of government statistics); cities without a value are left out and the hint says how many. `indicator` is refused with `level=powiat`, `min_transactions`, `market` or a price sort, and `value_desc` / `value_asc` without `indicator`. The values come from `statystyki/gov-map-stats` (one request); see [docs/mcp/tools/rank_locations.md](docs/mcp/tools/rank_locations.md). The server instructions and the description of `get_government_statistics` point to it for comparing many cities in one period.
- `rank_locations` / `stats cities`: `market` (`secondary` default, `primary`, `all`; CLI `--market`) for `level=powiat`, and `market`, `period_start` and `period_end` (the 12-month window) in a powiat result. Powiats without figures for the market are left out and the hint says how many. The names of powiats and of the 66 cities come from a table packaged in the wheel (generated by the maintenance script `recon/place_names.py`), so the 3.3 MB `map/tx-cities` is not fetched at run time (D19).
- Not-found answers say whether the place exists. After the service says „unknown” for a city, `get_market_statistics`, `get_transaction_statistics`, `search_offers` (first page, no `district`), `search_investments` (with `city`) and `get_developer` (with `city`) make one more request, `city-lookup` (the transactions dictionary, cached), and choose between „Nie znaleziono miejscowości o city_slug 'X'. Jeśli slug nie pochodzi z search_locations, weź go stamtąd; jeśli pochodzi, serwis nie ma dla niej tych danych: powiedz to użytkownikowi i nie ponawiaj.” and „Miejscowość 'Nazwa' istnieje, ale serwis nie ma dla niej <ofert | statystyk rynku | statystyk transakcji | inwestycji | aktywnych ofert tego dewelopera>. …” (`get_developer` and `get_market_statistics` add their own advice). A successful call costs no extra request; if the lookup fails, the earlier message stays. The server instructions gained a sentence: when an error says the place exists but the service has no data for it, do not guess other slugs and tell the user. See [docs/mcp/README.md](docs/mcp/README.md#errors).
- `search_offers` / `offers search`: an unknown `district` reads the city's districts once (`city-districts`). A name written otherwise (case, Polish letters, spaces, dashes: `PragaPołudnie`, `srodmiescie`, `Praga Północ`) is requested once more under the service's slug; a name that is no district gets „Znane dzielnice tego miasta …” with up to 25 real names (or that the service gives no districts for the city). The description of `district` was relaxed accordingly (it no longer requires the exact spelling of `search_locations`).

### Changed
- **BREAKING:** `rank_locations` / `stats cities`: when `--min-transactions` / `min_transactions` is not given and the sort is by price (`price_per_m2_desc`, `price_per_m2_asc`; both levels), places with fewer than 20 transactions are now left out. `transactions_desc` keeps 0; an explicit value, including 0, always wins. The MCP argument is now an integer or null with default null (it was an integer with default 0); the output `min_transactions` echoes the applied threshold; the hint says so when the default left places out. The refusal message gained „albo pusty”. For all places use `min_transactions=0` / `--min-transactions 0`.
- **BREAKING:** `rank_locations` output schema: `min_transactions` and `items[].transaction_count` are no longer required (an indicator ranking has neither); a transaction ranking still always emits both. A consumer that validated the strict schema and relied on them must accept their absence. The description of `rank_locations` and the schemas of its parameters and fields changed (two modes: transactions and indicator), and so did the text of the server instructions: `rank_locations bez indicator` is listed under the RCN prices and `z indicator` under the official statistics.
- **BREAKING:** `get_building`: the output field `name` is optional (a blank address from the register is absent instead of an empty value). Consumers validating the strict output schema, where `name` was required, must accept its absence. In CLI `--json` `name` is `null` and the text header falls back to the city.
- **BREAKING:** CLI exit codes for the service's answers (D21). A redirect is now 6 (was 4), a 410 is 6 (was 4), and a removed route, a 404 that is not the service's own "unknown" answer, is 6 (was 7); so is a 404 from a route that does not answer 404 for "unknown" (the offer lists and the developer page). Only the service's own "unknown" answers stay 7: a JSON 404 with an `error`, the 404 flight stream of the two statistics pages (`/statystyki/{location}/transakcje`, `/statystyki/{location}/dane-rzadowe`), and Next.js's 404 marker in the 200 of an offer list or of the developer page. Redirects are still never followed. A script must read 6 as „the service changed” and not retry. In MCP the same cases get one message that says the service moved the data and carries no HTTP status („Narzędzie nie może pobrać tych danych, bo serwis przeniósł je w inne miejsce albo przestał je udostępniać. To nie musi znaczyć, że argumenty są błędne ani że szukanego obiektu nie ma.”). See [docs/cli/README.md](docs/cli/README.md#exit-codes) and [docs/mcp/README.md](docs/mcp/README.md#errors).
- The ending of every contract-mismatch message is now „Serwis mógł się zmienić po aktualizacji. Nie ponawiaj tego wywołania: zgłoś to użytkownikowi.” (it was „Serwis mógł się zmienić po aktualizacji: ponawianie nie pomoże, zgłoś to użytkownikowi.”). The MCP server `instructions` gained the matching sentence („Gdy błąd mówi, że serwis mógł się zmienić, nie ponawiaj tego wywołania i powiedz o tym użytkownikowi; inne narzędzia mogą nadal działać.”), list the tools of each kind of price anew (the asking prices now include `get_offer`, `get_investment` and `get_developer`), say that the months of `get_transaction_statistics` are the secondary market only, that the official data come from NBP, GUS and Eurostat, and that its `location` is `polska`, an aggregate or a city slug. The `Szczegóły:` line (CLI) of a not-found is the target, the status and the media type, without the service's text; that of a redirect is `HTTP n -> <Location>` with the `Location` cut to 300 characters.
- **BREAKING:** `search_offers` / `offers search`: `city=polska` is refused before any request (CLI exit code 2), because the service has no list of offers of the whole country (its page for Poland is a list of cities); `items[].city` and `items[].city_slug` are removed from the MCP result, since a search is of one city (the CLI `--json` keeps them); `district` now reads the district's own list, `/ceny-ofertowe/{city}/{slug}/mieszkania`, with the slug made from the name locally (`Praga-Południe` becomes `praga-poludnie`), because `filterDistrict` no longer narrows the list on the service, and `list_url` of such a search is that list. A malformed `city` gets a text of its own (without „albo polska”); a not-found `page` above 1 names both readings („Serwis nie ma strony N tej listy albo nie zna miasta …”: the redesigned service answers a page past the last one like an unknown city); the truncated hint names the district („Zawęź filtry (dzielnica, cena, metraż)”). The descriptions of `status` (the `total` of `all` can exceed the sum of active and archived: T72), `sort` (the service's default order is not a ranking, so give `sort`), `page`, `name` and `last_price_change_kind` (`new_offer`) changed, and the prompt `znajdz_mieszkanie` asks for a `dzielnica` column.
- **BREAKING:** `get_developer` / `developers get`: `developer.website` and `developer.description` (CLI `--json`; the CLI text lost its „Strona dewelopera” line) and `cities[].avg_price` are removed, because the redesigned profile page gives none of them (the description says „Nie podaje strony www dewelopera”). `summary` is computed by the tool from the investments in the scope (averages weighted by active offers; it can differ by 1 zł from a row of `cities`, and `avg_price_per_m2` is not `avg_price / avg_area_m2`). `cities` are ordered by active offers, then by price per m², both highest first (the service's 1.0 main key; ties may differ). The page of a developer with investments in a single city has no chart of cities, so `cities` is derived from the investments and a city call says so („Serwis nie podał listy miast dewelopera: cities to tylko miasta inwestycji w city (wszystkie: city=polska).”; CLI header „Miasta dewelopera (tylko z inwestycji w [miasto]):”). The not-found text for a city adds „Albo deweloper nie ma w tym mieście aktywnych ofert: spróbuj city=polska.”. An investment is 350–400 characters of result (the default whole-country call 8 528). `get_market_statistics` (`top_developers`) is named as a source of `developer_slug`.
- **BREAKING:** `get_transaction_statistics` / `stats transactions`: a quarter's `average_price_per_m2` is replaced by `median_price_per_m2`, because the service's `avgPriceSqm` of a quarter is a median and 0.1.x mislabeled it (CLI column „Mediana PLN/m²”; in `--json` `average_price_per_m2` is `null` for quarters); the aggregates `7-miast`, `9-miast`, `10-miast` and `6-miast-bez-warszawy` are refused before any request (CLI exit code 2; their data come from `get_government_statistics`). Months now come from the city's statistics page, `/statystyki/{city}/transakcje` (`view.monthly`), since 2017 and for the secondary market only; the empty months after the newest one with transactions are dropped (Warszawa: 115 months, the last 3 incomplete). A month that holds transactions of another market gets its own error (CLI exit code 6) instead of a series that mixes markets, and quarters are „rynek nieokreślony”. The unknown-city text adds „Jeśli city_slug pochodzi z search_locations, serwis nie ma dla niego statystyk: powiedz to użytkownikowi.”. The CLI help says „Dane od 2017 r.; miesiące obejmują tylko rynek wtórny.”.
- `get_government_statistics` / `stats government` (the schema is unchanged): the page is `/statystyki/{location}/dane-rzadowe`, and 4 of the 8 datasets (`average_area`, `demography`, `unemployment`, `wages`) are read from its chart props, with the same values as before. The title and the description are „Statystyki GUS, NBP i Eurostatu”; the description no longer says „17 dużych miast” but „3 agregaty i część dużych miast (np. warszawa, krakow)” for `nbp_prices`, and its example city is `jastrzebie-zdroj` (the service's own list names it so; it said `jastrzebie`). `7-miast` has no `wages` or `unemployment`, and the schema and the error say so. A known location (`polska` and the 69 the service lists: 3 aggregates and 66 cities) that answers 404 is a changed service (CLI exit code 6), an unknown slug is not found (exit code 7). The wages of a city keep the `relative_to_poland` series.
- `get_market_statistics` / `stats market` read `GET /api/map/offer-snapshot/{city}` instead of the retired `offers/city-sales` (D20); the aggregates are computed in the process as before, from every active offer of the city as of `as_of`. The counts follow the source (Sopot: 8 offers, it was 6). A malformed `city` gets a text of its own („city: oczekiwano slug jednego miasta z search_locations: małe litery, bez polskich znaków (np. warszawa, sopot; nie polska); podano …”), and an unknown city „Serwis nie zna miasta X albo nie ma w nim ofert. …”.
- `get_investment` / `investments get --history`: the price history now comes from `ev` in the same response as the investment (the `sale-events` route is gone), so `include_history` costs no extra request and is not slower: the description no longer says „i powstaje wolniej” and the CLI help no longer says „(wolniej)”. It adds about 150 characters per offer (20 offers with history: 8–10 thousand characters; `limit` 200 with history on a 127-offer investment: about 58 500). The histories are read strictly: one offer off the contract fails the histories of the whole investment, and the message ends „Zamiast tego możesz pobrać inwestycję bez include_history albo historię jednej oferty przez get_offer.” (a new error, „dane z serwisu nie mają historii części ofert”, when the histories miss an offer). The error „Serwis nie ma historii cen ofert inwestycji …” is gone.
- Links: `list_url` (and the CLI line „Ta lista na deweloperuch.pl”) has no `page=1`, which the service redirects; `stats_url` of `get_transaction_statistics` is `/statystyki/{city}/transakcje`, and that of `get_government_statistics` is `/statystyki/{location}/dane-rzadowe#{section}` with the anchor taken from that location's own list of sections (it differs per location, e.g. `eurostat-demografia` for `polska`).
- The tools read the redesigned pages and routes only: the props of the build before 2026-10-29 (`initialData` of the offer list, the `data` and `sale` of the developer page, the 1.0 statistics page) are no longer read.
- `get_building`: a unit's `floor` and `rooms` are absent when the register's text is blank (they read 0); building averages, a trend quarter's price and the trend radius of 0 or less are no value.
- `estimate_property_value`: the estimate and the price per m² come as a pair; a value of 0 or less is no value. The CLI groups digits and agrees "z ostatniego miesiąca".
- Caching (D19): nine dictionary and index routes (`cities`, `city-lookup`, `city-districts`, `investments`, `developers`, `map/tx-cities`, `avg-price-trend/city/{citySlug}`, `statystyki/powiat-map-stats`, `statystyki/gov-map-stats`) are cached in the process for their freshness (`s-maxage`, else `max-age`) minus `Age`, at most 24 h; when served past their freshness they are kept for the freshness itself, at most 24 h. Every other route keeps the 300 s cap. Still in memory only, no disk cache. See [docs/configuration.md](docs/configuration.md#package-client).
- Descriptions of the tools `rank_locations`, `get_transaction_statistics`, `estimate_property_value`, `get_building`, `search_offers`, `get_developer`, `get_investment`, `get_market_statistics` and `get_government_statistics` (the title of the last is now „Statystyki GUS, NBP i Eurostatu”) and of their parameters and fields changed (see the pages under `docs/mcp/tools/`).
- Maintenance, not part of the package: the live e2e request budget is 170 (was 120); see `tests/e2e/README.md`.
- Maintenance, not part of the package: releases automatically render and attach a changelog PNG from short Polish copy in `packaging/announcements/<version>.json`. The release workflow can also regenerate only the graphic for an existing release.
- Maintenance, not part of the package: the bundle scanner `recon/scan_bundles.py` no longer ends the scan at the first moved or missing page. A page of `PAGES` that answers a redirect within the site (never followed), 404 or 410 is recorded and the scan goes on with an incomplete result, so one scan lists every such page. The exit code for it is 0 in a plain run and 6 with `--compare` or `--baseline-out` (it was 4, which stopped the scan there and left the rest of the pages and all chunks unscanned); when every page is skipped it is 6, with its own message. `--json` gains `redirects` and `missing`, and the text output a section `## strony pominięte (zaktualizuj PAGES)`. A redirect to another host, any redirect, 404 or 410 of a chunk and every other HTTP or network error still end the scan with 4, a STOP with 3. A redirect's `Location` is printed escaped and cut to 300 characters, also by `recon/probe.py`. See [docs/configuration.md](docs/configuration.md#development-scripts-recon).
- Maintenance, not part of the package: `recon/scan_bundles.py --save-pages DIR` keeps the HTML of every page that answered 2xx, byte for byte, in `DIR/<name>.html` at no extra request, for offline analysis only (never as samples or fixtures: pages may hold personal data). `DIR` must be new or empty and outside the repository, else the exit code is 2 before the first request; directories get mode 0700, files 0600 (POSIX), and nothing is overwritten.
- Maintenance, not part of the package: `PAGES` of `recon/scan_bundles.py` follows the redesign of deweloperuch.pl of 2026-10-29 (24 pages, was 22): `/statystyki/warszawa/transakcje` and `/statystyki/warszawa/dane-rzadowe` replace the two statistics routes that moved, and `/ceny-ofertowe/polska/miasta` and `/statystyki/polska/oferty` are new.

### Removed
- Internal, not part of the interface of the package: the hashed `_rsc` token (`flight.rsc_token` and its re-export in `recon/config.py`; the service now expects an empty `_rsc`, `with_rsc_token`), the reader of the retired route `offers/city-sales` (D20) and the readers of the removed routes `investments/{id}/sale-events` and `monthly-transaction-stats`.

### Fixed
- `rank_locations` / `stats cities`: a price or area of 0 from the service is no value. The place sorts last on price and shows no price fields (CLI text `?`, `--json` `null`); before, Ignatki-osiedle (listed with 0) ranked as the cheapest place [P 2026-10-15].
- `get_developer` / `developers get`: a price or area of 0 from the service is no value. The service writes 0 for the averages of a developer without active offers in that city; the result showed an average price of 0 PLN next to "0 active offers" (now CLI text `?`, `--json` `null`). The averages of the page's investments and its cities follow the same rule.
- `get_building` / `buildings get`: units with an unknown floor no longer show "piętro 0".
- `search_offers`, `get_developer`, `get_government_statistics`, `get_market_statistics`, `get_transaction_statistics` and the price history of `get_investment` (CLI `offers search`, `developers get`, `stats government`, `stats market`, `stats transactions`, `investments get --history`) work again after the redesign of deweloperuch.pl of 2026-10-29, which answered their requests with a redirect, a 404 or other data. Pages are requested with the empty `_rsc` the service now expects and the first page of a list without `page=1`; the offer list is read from its props `sales` and `serverPaginationData`, the developer profile from its hero and chart of cities, the government statistics from `/statystyki/{location}/dane-rzadowe`, the months of transaction statistics from `/statystyki/{city}/transakcje`, the offer-market statistics from `map/offer-snapshot` and the history from `ev`. What each change means for the output is in the entries under Changed. The two follow-ups recorded as expected failures of the live e2e suite are repaired too (next two entries).
- `rank_locations` / `stats cities` with `level=powiat` work again (exit code 6 before): the ranking is read from `statystyki/powiat-map-stats`, a 12-month window named by `period_start` and `period_end`. The two known powiat-level limitations (no route; counts over many years) are gone from the documentation; whether the prices are means or medians is still open (T85).
- `get_developer` / `developers get` of a known developer asked for in an unknown city is a not-found now (CLI exit code 7), not the „service changed” message (exit code 6) (T39, D21 exception): the service's page for that pair carries a redirect to the developer's whole-country page, which the tool reads as „unknown”.
- The MCP server log no longer prints „Szczegóły: None” for an error without details.
- Thanks to [jamtujest](https://github.com/jamtujest) for the first repair attempt, [#15](https://github.com/MBratkowski/deweloperuch-mcp/pull/15): its four 2.0 page captures (`tests/fixtures/rsc/*_20261030.rsc`) and two samples (`page.developer.v2`, `page.offers_list.v2`) are kept, and its idea of validating a page's data inside the transport's decode, so that a refused reply is never cached, was adopted. The tool code of this release is the project's own, on a shared core, so the per-tool changes of #15 were replaced, not merged. Thanks also for [#16](https://github.com/MBratkowski/deweloperuch-mcp/pull/16), which moved the market statistics to the offer snapshot at the same time: it is merged with this release's market code kept; its Wrocław capture (`tests/fixtures/api/offer_snapshot_wroclaw_20261030.json`) and sample (`api.offer_snapshot.wroclaw`) are kept, and its Wrocław figures, which its author found to match the service's own summary that day, are now a test of `get_market_statistics`.

## [0.1.3] - 2026-10-16

### Added
- Native Windows support for the CLI, MCP server and shared request limiter, with standard-library file locking, PowerShell setup instructions and offline CI on Windows, macOS and Linux (Python 3.11 and 3.13). Windows support starts in 0.1.3. [#8](https://github.com/MBratkowski/deweloperuch-mcp/issues/8)
- Links to the project's [website](https://mbratkowski.github.io/deweloperuch-mcp-site/) and its [documentation in Polish](https://mbratkowski.github.io/deweloperuch-mcp-site/docs/), with a visual install guide, in the README.

### Changed
- Maintenance, not part of the package: a daily workflow (`.github/workflows/stats.yml`) archives GitHub traffic, release downloads, repository counters and PyPI downloads as CSV files on the `stats` branch. See [CONTRIBUTING.md](CONTRIBUTING.md#statistics-archive).
- New official icon (a builder in a hard hat labelled MCP+CLI) in the README and the Claude Desktop extension, in every size from 16 to 512 px (thicker strokes at 32 and 64 px, a hand-drawn 16 px version). It is used with permission of the deweloperuch.pl authors and is not covered by the MIT licence; see [NOTICE](NOTICE).

### Removed
- The old icon drawings `assets/icon-small.svg` and `assets/icon-tiny.svg`.

### Fixed
- Fractional-area valuations now warn in CLI and MCP hints that the service may ignore the fractional part; requested area and the upstream estimate remain unchanged, including when comparable transactions are truncated. [#6](https://github.com/MBratkowski/deweloperuch-mcp/issues/6)
- The CLI agent skill verifies this package's command groups before using an executable found on `PATH`; a legacy CLI with the same name uses the explicit package-qualified `uvx` invocation. [#7](https://github.com/MBratkowski/deweloperuch-mcp/issues/7)

## [0.1.2] - 2026-10-14

### Added

## [0.1.0] - 2026-10-14

### Added
- Claude Desktop extension `deweloperuch-mcp-<version>.mcpb` (one-click install, uv runtime, macOS and Linux; Windows is not supported) and an installable wheel and sdist, so the server also runs with `uvx --from git+https://github.com/MBratkowski/deweloperuch-mcp deweloperuch-mcp`. `make package` builds them, `make smoke` checks them. See [README](README.md#install).
- CI (`make fast` and the offline tests on every push and pull request) and a release workflow that builds the artifacts and attaches them to a GitHub release for every `v*` tag. See [CONTRIBUTING.md](CONTRIBUTING.md#packaging-and-releasing).
- MCP server `deweloperuch-mcp` (stdio, read-only) with 13 tools and the matching `deweloperuch` CLI commands. See [docs/mcp/README.md](docs/mcp/README.md) and [docs/cli/README.md](docs/cli/README.md).
  - Search and details: `search_locations`, `search_offers`, `get_offer`, `search_investments`, `get_investment`, `search_developers`, `get_developer`.
  - Statistics and valuation: `get_market_statistics`, `get_transaction_statistics` (RCN), `rank_locations`, `get_building`, `estimate_property_value`, `get_government_statistics` (GUS and NBP time series for Poland, aggregates and 66 cities; command `stats government`).
- `search_offers` / `offers search` filters `district`, `price_dropped`, `status` (`active`, `archived`, `all`) and `price_per_m2_min` / `price_per_m2_max`; sorts `price_per_m2_asc`, `price_per_m2_desc`, `area_asc`, `area_desc` and `biggest_drop`.
- `get_offer` / `offers get` return `price_flags`: lowest price of the last 30 and 90 days, number of price changes, largest drop and rise, and a `suspicious_reduction` flag.
- Links to the public pages of deweloperuch.pl in results (`list_url`, `investment_url`, `developer_url`, `stats_url`, `ranking_url`, `building_url`); see [docs/mcp/README.md](docs/mcp/README.md#links-to-service-pages).
- A request limiter shared by all processes (at most 1 request per second, one at a time) and an in-memory response cache (at most 300 s). See [docs/configuration.md](docs/configuration.md).
- A persistent STOP lock shared by all processes: after a 401, 403, 429 or a Cloudflare challenge no process sends requests until the lock expires (429) or is cleared by hand. New commands `deweloperuch stop status [--json]` and `deweloperuch stop clear`. See [docs/configuration.md](docs/configuration.md#stop-shared-lock-between-processes).
- Development tools: `make fast` and `make check` quality gates (ruff, mypy, import-linter, vulture, complexity and duplication reports), an offline test suite with real stored responses, golden outputs for the CLI and MCP server, and an opt-in live end-to-end suite (`DEWELOPERUCH_LIVE=1`).
- `recon/probe.py` and `recon/scan_bundles.py`, maintainer scripts for checking the service and detecting changes after a deploy. See [docs/configuration.md](docs/configuration.md#development-scripts-recon).

### Changed
- RCN unit and transaction identifiers in the samples and tests are pseudonymised.
- **BREAKING:** every MCP tool rejects arguments that are not in its schema (`additionalProperties: false`) with an error that lists the allowed names. Clients that relied on unknown arguments being silently ignored now get an error. Argument validation errors are now in Polish instead of the SDK's English text. See [docs/mcp/README.md](docs/mcp/README.md#errors).
- **BREAKING:** `recon/scan_bundles.py` goes through the shared limiter, fetches only a fixed list of pages and chunks, follows no redirects, does not retry and ends at the first error. `recon/flight.py` and the recon scripts require Python 3.11 or newer.
- With an active STOP lock, CLI data commands and the recon scripts end with exit code 3 without sending a request (before, they could wait or end with code 5).
- Error messages describe what happened and what to do, without service paths or response content; technical details are in the log (MCP) or on a `Szczegóły:` line (CLI). After a STOP the MCP server stays halted until it is restarted.
- The MCP server `instructions` explain the three kinds of prices (asking, RCN transaction, official NBP/GUS), sparing use and what to do on a STOP.
- Responses that the CDN serves past their freshness are cached for 300 s instead of not at all; `no-store`, `no-cache` and errors are still never cached.
- Internal: the package is organised into the layers `api`, `models`, `usecases` and `consumers` plus `bootstrap.py`, and the tests mirror it; entry points and behaviour are unchanged. See [CONTRIBUTING.md](CONTRIBUTING.md#architecture-rules).

### Fixed
- `search_offers` / `offers search` work on the live service again (the page data parser missed the data row after text rows).
- An unknown city gives "Serwis nie zna miasta ..." (CLI exit code 7) instead of a "service may have changed" error (code 6).
- The cache stores responses that have `max-age` but no `s-maxage`, respects `no-store` and `no-cache`, and no longer sends repeated requests while a response is fresh.
- One malformed GUS dataset no longer breaks the others on the statistics page.
- MCP validation errors no longer contain a link to the validation library's documentation.
